# 14. 会社が育つ（AI社員の憲法と、学習の輪）

2026-08-26。社長の指示「**hermes agent を全社員に導入したい**」と、
その前の問い「他に AI の考え方を固めないといけないのってある？」への答え。

元にしたのは **[NousResearch/hermes-agent](https://github.com/NousResearch/hermes-agent)（MIT）** —
"The agent that grows with you"。閉じた学習の輪を持つ自己改善エージェント。

---

## そのままは持ち込めない

archify（→ 11）のときとまったく同じ形だった。

| Hermes が要るもの | OneFound |
|---|---|
| Python 3.11 ＋ Node ＋ ripgrep ＋ ffmpeg ＋ Git | Cloudflare Workers（workerd） |
| `~/.hermes/` のディレクトリ | ファイルシステムが無い |
| CLI ＋ ゲートウェイの2プロセス、7つのターミナルバックエンド | 1つの Worker |
| SQLite の FTS5 | Postgres（Supabase） |

**持ち込んだのは「輪」だけ。** コードは1行も使っていない。

**確かめていないこと**: Hermes のスキルは
[agentskills.io](https://agentskills.io) の標準に沿うとあるが、
**その仕様はこの環境から読めなかった**（egress ブロック）。
OneFound の SKILL.md は Claude Skills の形なので、たぶん互換だが、突き合わせていない。

## 0. まず、社員の憲法（`lib/roster/constitution.ts`）

輪より先に、**土台が無いことが分かった**。

統括AIには94行の憲法があるのに、AI社員の頭に載るのは
**自分の定義（任務1文 ＋ ルール3〜5行）と道具の使い方だけ**だった。
「分かったふりで書かない」「確かめていないことを言い切らない」
「社長でないと決められないことは止まる」は製品のあちこちに書いてあるのに、
**社員は一度も読んでいなかった**。

だから7人ぜんぶに同じ1枚を載せる。**定義の前**に置く（社員が変わっても変わらないので、
ここがプロンプトキャッシュの境目になる）。

**短くする。** 社員は standard（速いモデル）で走るので、
統括AIと同じ量を載せると定義のほうが薄まる。

**7人ぶんに同じ行を書き足さない。** 定義は「その人が誰か」だけを言う場所。
だから 調査担当の「数字には必ず根拠を付ける」と
戦略担当の「価格・対象は ask_decision で聞く」は**憲法に上げて、定義からは消した**
（同じことを2回書かない）。

**根拠の穴を、正直に埋めた。** 調べる道具（Web検索）は既定オフなので、
社員は自分の記憶から書くしかない。だから憲法に1行 —
「**調べる道具が渡されていないなら、記憶から書いたことに『未確認』と印を付ける**」。
道具が入るまでは、これが正直な形。

**社長にも見える**（メンバー画面 → 全員に効くこと）。標準スキルと同じ考え方 —
何を読んで働いたかが見えないと、成果物の質を判断できない。
ただし**切れない**（ロスターの Critical Rules と同じく、会社の土台）。

## 1. 社員がスキルを書く／使いながら直す

Hermes: *"Autonomous skill creation after complex tasks"* / *"Skills self-improve during use"*

道具を2つ足した（`lib/run/tools.ts`）。

| | |
|---|---|
| `write_skill` | **同じ形の仕事がまた来る**と分かったときだけ、やり方を手順書にする |
| `improve_skill` | 渡された手順書に足りないところがあったら、直した全文を出す |

**学びとの違いを、道具の説明に書いた。**
学び（`note_learning`）は1行の申し送りで、**次の実行に必ず載る**。
スキルはそれより重く、**必要なときだけ読まれる**ので量を書ける。
「またやることになる仕事の、やり方」がスキルで、「次の自分への一言」が学び。

**渡した手順書だけ直せる。** `improve_skill` の id は、その往復で依頼文に載せたものに限る
（当てずっぽうの id で他の行に届かない）。

**1タスクで1枚まで。** 書き散らかされると、通す側も読む側も溺れる。

**ファイル名は英数字が残らなければ番号にする** — MCP の道具名で踏んだのと同じ事故
（「テストの在庫」→ `______`）をここでも起こさない。

**書いたスキルは会社ぜんぶのものになる**（`employee_id` は null）。
会社が学ぶのであって、席が学ぶのではない。

**ついでに塞いだ穴**: 実行は会社ぜんぶのスキルしか読んでいなかったので、
設定ペインで社員に付けたスキルは**一度も読まれていなかった**。担当のぶんも読むようにした。

## 2. 通すのは統括AI（社長が選んだ形）

ここで OneFound の決めごとと**正面からぶつかった**。

Hermes は社員が**自分で**自分を書き換える。OneFound には先の判断がある —
「**ルールには自動で書かない。勝手に増えると、社長が知らないうちに社員が変わる**」。

社長に3つ出して選んでもらった。

| | |
|---|---|
| 社員が書いて、そのまま使う | Hermes のまま。速いが、決めごとと衝突する |
| **統括AIが通す** ← **選ばれた** | 社長の手は増えない（やることは4つのまま）。往復が1つ増える |
| 社長が有効にするまで使わない | 器はそのまま使えるが、溜まるだけになりやすい |

`lib/exec/skills.ts`。**1往復で、待っているものを全部見る**（1枚ずつ見ると、
社員が3枚書いた日に3回払う）。判定の基準は3つだけ —
① 次に同じ形の仕事が来たとき本当に読めるか ② この1回の結果ではなく「やり方」か
③ もうある手順書と同じことを言っていないか。**迷ったら落とす**。

**鍵が無い環境でも通す。** ここを黙って飛ばすと下書きが永久に溜まって、
輪が一度も回らない。ただし**仮の審査だと名乗る**（判定の理由に残す）。

**落としたものは残す。** 理由つきで `/skills` の下に暗く並ぶ
（メンバー画面で「まだいない人を暗く並べる」のと同じ置き方）。
**社長はトグル1つで戻せる** — 「戻す」ボタンを別に置かない。

**直しを落としたときは、行に印を残さない。** 戻せるものが無いのに
「統括AIが落としました」と出ると、**手順書そのものが落ちたように読める**。
直したがったことは、そのタスクの歩みに残っている。

## 3. 記憶の手入れ（`lib/exec/memory.ts`）

Hermes: *"Agent-curated memory with periodic nudges"*

学びは1人30行、社長のことは20行が上限で、**あふれたら古いものから落ちて**いた。
落ちるのは「古いもの」であって「もう要らないもの」ではない —
一度きりの気づきが残り、毎回効く大事な1行が押し出される。

だから満杯に近づいたら（学び24行／社長のこと16行）**畳んで濃くする**。
**捨てるのではなく、まとめる。**

**いつも呼ばない。** 溜まったときだけ。ふだんの実行に1往復ぶんの上乗せをしない。
**元より悪くしない** — 畳んだ結果が空か、行が減っていなければ、畳まなかったことにする
（計画の引き直しと同じ守り）。

## 4. 思い出す（`lib/exec/recall.ts`）

Hermes: *"FTS5 session search with LLM summarization for cross-session recall"*

前まで渡していたのは —
その Work の済んだ成果物3件（本文）／ 承認された成果物の**タイトルだけ**／
その Work の決めたこと。つまり**別の Work で調べたことの中身は、どこからも届いていなかった**。
憲法に「会社がもう知っていることは、二度調べません」と書いてあるのに、
知っているものを渡していなかった。

**日本語で効く探し方を選ぶ必要があった。**

| | |
|---|---|
| `to_tsvector` | 日本語を切れない（語の境目が無い）→ 使わない |
| pgroonga | 日本語に強いが専用の演算子が要る。PostgREST から使うには `public` に関数が要り、**それだけでセキュリティ警告が1件増える** |
| **`ilike` ＋ pg_trgm の GIN** ← 採った | 素の絞り込みで書けて、index が効く。**関数を置かないので警告は0件のまま** |

探す先は3つだけ — **作ったもの / 決めたこと / 会話**。会社の記憶はこの3つに全部ある。

**探す言葉は、ひらがなを捨てて拾う**（`termsOf`）。
「収益モデルを比べる」→「収益」「モデル」。乱暴だが、形態素解析を積むより
**ずれ方が読める**（外したときに理由が分かる）。
**どこにでも当たる言葉は捨てる**（「会社」「今回」で探すと全部当たる）。

**往復は増やさない。** 読む道具としてモデルに渡すと 1タスク=1往復 が崩れるので、
**こちらが先に引いて、依頼文に載せる**。タダで、待たせない。

## 5. 社長のこと（`founderNotes`）

Hermes: *"Honcho dialectic user modeling"* / `USER.md`

学びが「社員が仕事から覚えたこと」なら、こちらは**会社が社長から覚えたこと**。

**モデルを呼んで作らない。** 起きた事実をそのまま1行にする（朝の報告と同じ考え方）。

| いつ | 何を覚えるか |
|---|---|
| 判断に答えたとき | 「◯◯」では「△△」を選んだ |
| 成果物を差し戻したとき | 差し戻したときに言ったこと: … |

置き場は学びと同じ表（`agent_skills` の `source='learned'`）で、
**`employee_id` が null のほうが社長のぶん**（スキル・設定と同じ書き方 — 表を増やさない）。

読むのは3か所 — 統括AIの計画 ／ 統括AIの会話 ／ AI社員の依頼文。

**見える・消せる**（メンバー画面 → 全員に効くこと → 社長のこと）。
見えないところで会社が社長像を作らない。

## 6. 育つと壊れるところを、先に直した（同日）

社長の言い直し「**AI社員が hermes みたいに学習していって欲しい**」で読み直して、
**棚が増えたときに効かなくなる**ところが2つ見つかった。

**① 「いつ読むか」を誰も読んでいなかった。**
道具の説明には「ここが合っていないと誰も読めない」と書いて `when` を書かせているのに、
選ぶ側は **`name` の字の重なり**だけを数えていた（「の」「を」「方」が当たるだけで上位に来る）。
社員が手順書を書けるようになった以上、ここは効く — **棚が増えるほど、当てずっぽうは悪くなる**。
思い出すのと同じ言葉の拾い方（`termsOf`）に揃え、**`desc` も見る**ようにして、
**フェーズ名とねらいも手がかりに入れた**（「調査のまとめ方」は、タスク名ではなくフェーズが言っている）。
**1枚も当たらなければ載せない** — 関係ない手順書は、読ませるだけ無駄で、高い。

**② 差し戻しが、手順書に返っていなかった。**
社長の指摘は担当の**学び**にだけ残り、**その仕事の土台になった手順書は直らないまま**だった。
Hermes の「使いながら良くなる」が半分しか回っていない。

直しのタスクには**同じ手順書が載る**（題が同じなので同じものが当たる）ので、
依頼文に一言添えるだけで輪が閉じた — **覚えておく場所を増やさずに済んだ**。
「この手順書に沿って作ったものが差し戻されました。手順書のほうに足りないところがあったなら、
improve_skill で直してください（社長の指摘が、あなた1人の記憶で終わらないように）」。

## 判断ログ

- **輪だけ持ち込む**（コードは持ち込めない）。archify と同じ形
- **通すのは統括AI**（社長が3案から選んだ）。社長の手は増やさない
- **落としたものは残す**。理由つき。トグル1つで戻せる
- **表を増やさない**。社長のことは `agent_skills` の1行（学びと同じ書き方）
- **`public` に関数を置かない**。セキュリティ警告0件を優先して、探し方を `ilike` に決めた
- **往復を増やさない**。思い出すのは往復の前に、こちらが引く
- **憲法を先に入れた**。輪より土台が先 — 何を守るかが決まっていない社員が学んでも、学ぶ方向が決まらない

## まだ

- **調べる道具**（Web検索）は既定オフのまま。憲法の「未確認と印を付ける」は
  そこが埋まるまでの正直な形であって、答えではない
- スキルの書式を agentskills.io と突き合わせる（この環境からは読めない）
- 社員ごとに手順書を分ける（いまは会社ぜんぶのもの）

# 後半: Hermes を、こんどは Claude Code 側に（2026-08-27）

社長の指示「**この今の Claude Code に hermes agent 導入して**」。

前半（8/26）は **OneFound の AI社員**に輪を入れた。今回は **その OneFound を作っている
Claude Code 自身**に同じ輪を入れる。`.claude/` はそれまで**空だった**。

## 何が起きていたか

毎回のセッションで、同じことをやり直していた。

- `npm install` → `npm run build` → headless chrome を手で立てる
- 検査の走らせ方（**新しいポートで新しいサーバー**・`sleep` でつながない・
  `DEMO_MODE=1`）を、思い出しながら組み立て直す
- `openrouter.ai` に出られないこと、`死 12` が正常なこと、を毎回発見し直す
- **`sh /tmp/killnext.sh` に頼っていた** — 器が入れ替わると消えるので、
  新しいセッションの自分には存在しない道具だった

つまり **Hermes が直そうとしている状態そのもの**だった。
やり方は僕の頭の中（＝そのセッションの文脈）にしか無く、次の自分には渡らない。

## 写した先

| Hermes | Claude Code |
|---|---|
| 憲法（always-on） | `CLAUDE.md`（もとからある） |
| スキル（必要なときだけ読む手順書） | **`.claude/skills/<name>/SKILL.md`** |
| 使いながら直す | 手順が違ったらその場で SKILL.md を書き換える |
| `USER.md`（user modeling） | **`.claude/USER.md`** |
| 記憶の手入れ | （まだ。下の「残っていること」） |
| 思い出す（cross-session） | `docs/PLAN.md` の判断ログ ＋ git の履歴（もとからある） |
| 起動時の nudge | **`.claude/hooks/session-start.sh`** |

**入れたもの**

- `checks` — 器の立て方と待ち方、検査4つ（`run` / `layout` / `reach` / `dead`）、
  `_walk` の使い方、chrome が落ちたときの立て直し、**この環境で出られない先**
- `probe-model` — 本物のプロンプトを本物のモデルに通して**中身を判断する**やり方。
  `tsx` で依頼文を本体から出す（記憶で書かない）／`reasoning_effort: high` は
  詰まりやすい（実測: thinking だけで 9,140トークン・本文が空）／
  **社長役は自分でやる**（空欄で測ると、製品が薄いのか測り方が悪いのか区別できない）
- `USER.md` — 順番のくせ（作る → 整える → 公開 → 広げる）、
  報告のしかた（直した報告より、何が嘘だったかを先に）、言葉（状態は6語）。
  **覚えた経緯も一緒に残す** — 消すときの手がかりになる
- `tools/check/kill.sh` — `/tmp` に置いていた道具をリポジトリへ

## 決めたこと

**スキルは「手順」だけを書く。** 何を作るかは `CLAUDE.md`、どう進めるかは `USER.md`、
**どうやるか**がスキル。3つが同じことを言い始めたら、どれかが要らない。

**書いたら、その場で1回使って確かめる。** このスキルも、書いたあと
`layout.mjs` を手順どおりに走らせて 18画面が通ることを見てから残した。
（OneFound 側の「統括AIが通す」に当たるものは、ここでは**社長が commit を読む**）

## 残っていること

**`CLAUDE.md` の手入れ**（Hermes ③）。いま 1,900行を超えていて、毎セッション全部読む。
学びが増えるほど重くなるのは、まさに Hermes が「畳んで濃くする」で解いた問題。
ただし**これは会社の記録**でもあるので、勝手に畳まない。社長の判断を待つ。
