# 13. つないだ道具（MCP）

2026-08-25。社長の言葉:

> 将来的にはMCP接続もできるようにしたいけど、MCP構築時間かかりますか？できそうならしてください

## かかった時間と、なぜ「できた」か

**半日。** 大きいのは protocol ではなく、**誰として読み書きするか**のほうだった —
そしてそこは、Cron の runner を作ったときに一度通った道なので、答えがもう出ていた。

もう1つ効いたのは、**話す相手をこの repo の中に置いた**こと（`tools/mcp-test/server.mjs`）。
この環境から外には出られないし、出られたとしても
**他所のサーバーの調子で検査が赤くなるのは検査ではない**。

## 向きは2つある。作ったのは client のほう

| | だれが何を | 作ったか |
|---|---|---|
| **client** | **OneFound の AI社員が、社長の道具を読む・書く** | **作った** |
| server | 社長の Claude が、OneFound の中を読む | まだ |

社長が「MCP接続」と言うとき欲しいのは、ふつう client のほう —
**AI社員が、社長がふだん使っているものをそのまま触る**。
server の側は、鍵をどう配るか（OAuth か、長生きするトークンか）が別の設計になるので分けた。

## 決めたこと

- **相手ごとの実装を持たない。** MCP は道具の側が「どんな道具があるか」を自分で名乗る。
  こちらは**名前を付け替えて並べるだけ**（`lib/mcp/company.ts`）
- **ライブラリは入れない。** Streamable HTTP は **JSON-RPC 2.0 を POST するだけ**で、
  返事は JSON か SSE。それだけなら `fetch` で足りる（workerd に載るかを確かめる手間も要らない）
- **会社に対して1つ**（社員ごとではない）。会社ぜんぶのスキルと同じ置き方
- **本番は https だけ。** `http://` を許すと鍵が平文で飛ぶ。
  localhost は**デモと検査**のためだけに通す（`DEMO_MODE`）。
  **`NODE_ENV` では分けられない** — `next start` は検査のときも production なので、
  そこで切ると「検査のためだけに本番の判定を緩める」ことになる
- **書ける道具は、社長が許した相手のぶんだけ。** 既定は読むだけ。
  相手が `readOnlyHint` で「読むだけ」と言っているかは参考にするが、**鵜呑みにはしない** —
  決めるのは社長が入れた設定のほう。**外に出る道具は Approval 必須**の一形
- **道具の名前に日本語を入れない。** `mcp__<先>__<道具>` の `<先>` は英数字だけ。
  「テストの在庫」は寄せると `______` になり、`mcp________list_items` という
  読めない名前ができる（実際そうなった）。英数字が1文字も残らなければ**並び順の番号**にして、
  どこの道具かは**説明のほう**で言う（説明は日本語のまま出せる）
- **倒れない。** 相手は他人のサーバーなので、落ちていても遅くても当たり前。
  失敗は例外ではなく**文字**で返して、社員にも社長にも読ませる。
  待つ上限は 15秒（名乗り）/ 45秒（呼ぶ）
- **繋がっていないなら、そう出す。** 一覧に並んでいるのに何も呼べない、を作らない。
  1つ落ちているせいで仕事が始まらない、も作らない（黙って飛ばして、理由は一覧に残す）
- **鍵は行って戻らない。** 画面に返す型（`McpServer`）に `token` を置かない。
  DB の列の権限で止める形も試したが、引くために `public` の SECURITY DEFINER が要り、
  **それだけで警告が1件増える**（`authenticated_security_definer_function_executable`）。
  **スキーマ由来の警告0件は守る** — そして会社の利用者が自分で入れた鍵を
  自分で引けることは、そもそも隠す必要が無い。止めたいのは
  「一覧を引いたら鍵まで画面に届いていた」のほうで、それは**型で守る**

## 1タスク＝1往復の、初めての例外

`lib/run/worker.ts` は**1タスク＝1往復**だった。それは道具が全部「書き残す」系で、
往復する理由が無かったから成り立っていた（→ CLAUDE.md
「Web調査のような『読む』道具が入るときに初めてループが要る」）。

MCP は**読む道具**なので、読んだ結果を見てから書くことになる。

- **つないでいない会社では、これまでどおり1往復** — 払う理由が無いのに往復しない
- 上限は **3往復**（`MCP_ROUNDS`）。読む・確かめる・書く で足りるし、
  上限が無いと相手のサーバー次第でいくらでも払うことになる
- 成果物を書いたか、判断で止まったら、道具を呼んでいてもそこで終わり
- **結果は「社長の発言」として渡す。** 器（`Msg`）は role と文字しか持たない —
  道具の往復を本物の形で入れるには3つの通り道を直すことになる。
  ここでやりたいのは「読んだものを見せて、続きを書かせる」だけなので、
  **宙に浮いた tool_call を作らない**この形のほうが安全でもある
- 呼んだことは**歩み（run_steps）に残る**。演出ではないので、失敗も残る

## 画面

スキルとまったく同じ置き方 — 左レールには出さない。

- **`/tools`** … つなぐ / 切る / 書けるようにする / 外す。1件を開くと**相手が名乗っている道具**が並ぶ
- **メンバーの「全員に効くこと」** … 一覧と入/切だけ（会社ぜんぶに効くものなので、ここに置く）

## まだやっていない

- **OAuth。** いまは「鍵を貼る」だけ。Notion や Linear のような
  OAuth を要る相手には、まだつなげない
- **社員ごとに道具を分ける。** `agent_skills` と同じく `employee_id` の列を足せば入る
- **server の側**（社長の Claude が OneFound を読む）
- **呼んだぶんの記帳。** MCP の呼び出し自体はトークンを使わないが、
  往復が増えるぶんは `token_ledger` に乗る（そこは既に正しい）
