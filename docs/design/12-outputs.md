# 12. 出す形（成果物のフォーマット）

2026-08-25。社長の言葉:

> もちろん文章だけでなく、LPやPDFや様々な出力できるようにしたい、CSVとかもそうだし

## なぜ

ここまで成果物は **markdown 1種類**だった。本文は `<pre>` に流していたので、
`## 見出し` も `|---|---|` も記号のまま並んでいた。読めはするが、
**社長の手もとで使える形ではなかった** — 価格表は表計算に入らず、
LPは書けず、報告書は人に送れない。

一人社長がAI社員に頼むのは、たいてい**その先に渡す相手がいる仕事**である。
表計算に入れる、ブラウザで開く、PDF にして送る。
**持ち出せない成果物は、無いのと同じ。**

## 形は1か所で決める

`lib/deliver/format.ts` の `FORMATS` が唯一の表。見るのは4か所 —
AI社員の道具（何を書けるか）／ 画面（どう描くか）／ 持ち出し（拡張子と型）／
一覧の書き出し。**業種は入れない**（何の会社でも同じ形）。

| kind | 語 | 中身 | 画面 | 落とすと |
|---|---|---|---|---|
| `report` | 報告 | markdown | 見出し・箇条書き・表に組む | `.md` |
| `doc` | 文書 | markdown | 同上 | `.md` |
| `copy` | 文案 | markdown | 同上 | `.md` |
| `table` | 表 | markdown の表 | 表に組む | `.md` |
| `csv` | 表データ | CSV | **表に組む**（1行目が見出し） | `.csv` |
| `page` | ページ | 1枚の HTML | **下見**（sandbox の中） | `.html` |
| `code` | コード | ソース | 等幅のまま | `.txt` |
| `diagram` | 図 | archify の IR | **図として描く**（→ 11） | `.json` |
| `image` | 画像 | **バイト列**（`storage_path`）＋ 頼んだ言葉 | 白い面に絵 | `.png` |
| `audio` | 音声 | **バイト列**（`storage_path`）＋ 読み上げた台本 | その場で聞ける | `.mp3` |

**種類が先、中身は後。** 種類が言っていないときだけ中身で見分ける
（`{` で始まれば図、`<!doctype` で始まればページ）。

## 決めたこと

- **markdown は器ではなく、読み方。** ライブラリは入れない
  （`lib/deliver/md.ts` は 7つの段落と 3つの飾りだけを受ける）。
  受けないものは**素の段落にする** — 捨てない
- **書体のウェイトは 400 のまま。** 強調は明るさで言う（`T1` と `T2` の差）。
  デザイン言語の「ウェイトは 400 のみ」は成果物の中でも守る
- **表は外枠を持たない。** ヘアラインだけで区切る（「並ぶものはヘアラインだけで区切る」）。
  広い表は**横に送る**（`.sx`）。文字は縮めない
- **ページ（LP）はアプリの中で走らせない。** 中身はモデルが書いた文字列なので、
  そのまま描くと**このアプリの中で script が動く**。`sandbox=""` ＋ `srcdoc` に閉じ込める —
  別のオリジンになるので、こちらの cookie も DOM も見えない。
  見えるのは**組み方と字面**で、それが下見に要るものの全部
- **PDF は刷って作る。** サーバーで PDF を組む道具は入れない（workerd に載らないし、
  書体を抱えるとビルドが太る）。ブラウザの印刷には「PDF に保存」がもとから付いていて、
  それが**いちばん確かな PDF**。**新しい窓は開かない**（ブロックされると何も起きない）—
  見えない iframe に1枚組んで、その中の窓に刷ってもらう
- **紙は白い。** 画面の黒をそのまま刷らない（`printable`）。
  ここだけはデザイン言語の外 — 人に送るものであって、アプリの中の面ではない
- **一覧の書き出しは、形ごとに違うところから取る。**
  図は主線、表は見出しの行、ページは `<title>` と最初の1文。
  JSON も `|---|` もそのまま出さない
- **種類ごとに別のボタンを並べない。** 持ち出しの器は1つ（`DelTake`）で、
  拡張子と型が形から決まる

## 道具の側

`write_deliverable` の説明に、**種類ごとの本文の書き方まで**入れてある。
`csv` なのに markdown の表を書くと1列の表になるので、そこは説明で止める:

- markdown のもの … 見出し `##`・箇条書き `-`・表 `| a | b |` で 1000〜4000文字
- `csv` … **1行目が見出し、2行目から数字**。説明文も markdown も混ぜない
- `page` … `<!doctype html>` から始まる**1枚で完結した HTML**。
  外部のファイル・画像・スクリプトは読み込まない（**そのまま公開できること**が条件）

**決め打ちのプロバイダも同じ形で返す**（`lib/ai/fake.ts`）。
markdown で返していると、「csv なのに markdown を書く」という本番の壊れ方が
検査に永久に出てこない。

## 中身がバイト列の2つ（画像・音声）

`image`（2026-08-27）と `audio`（同日・社長の「他のやつから順に」の④）は、
ほかの8つと**形が違う** — 中身が文字ではないので、`body` には入らない。

- **バイト列は `deliverables.storage_path`**（0001 から空いていた列）。
  Supabase Storage に private で置き、画面が読むのは**その都度作る署名つき URL**（1時間）
- **`body` に何を入れるかは、形で違う** —
  画像は**何を頼んだか**（一言＋プロンプト。絵の中の字は読み違えられるので、ここにも書く）／
  音声は**読み上げた台本そのもの**（聞く前に中身が分かるし、差し戻すとき指せる）
- **道具は `write_deliverable` の代わり**（`make_image` / `make_voice`。両方は呼ばない）
- **1回だけ頼み直す。** 本番でいちばん起きる壊れ方は「絵の説明を書く」「台本を書く」で終わること。
  道具を1つに絞って `toolChoice: 'required'`（`rewrite` / `redraw` と同じ形）。
  **同じ題にすれば、版の仕掛けが文章のほうを一覧から隠す** — 消す口は作らない
- **渡すのは担当と栓の両方が揃ったときだけ** — 画像はデザイン担当、音声は執筆担当
  （読み上げるのは**言葉を書く人の仕事の続き**なので、担当を増やさない）。
  どちらも**既定はオフ**（従量課金。0036 / 0039）
- **原価は同じ台帳に、同じトークンで載る。** ただし**単価は別々に数える** —
  画像も音声も、文字のモデルとは桁が違う（混ぜると残高が嘘になる → 0034 で踏んだ穴）
- **音は紙にならない**（`print: false`）。サムネイルも分ける —
  絵は縮めた絵そのもの、音は**台本の書き出し**（`src` があるかどうかで決めると、
  mp3 を `<img>` に渡して**壊れた絵**が出る）
