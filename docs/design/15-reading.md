# 15. 読む — URL を1本読む

2026-08-27。社長の「他のやつから順に」の①。

## なぜ

ここまで AI社員に渡せる材料は、**社長が ＋ で落としたファイルだけ**だった。
検索（OpenRouter の web プラグイン）はあるのに「**このページを読んで**」ができず、
取り込みの URL は一覧に**待機のまま**並んで、中身は一度も読まれていなかった。

「読めないものを読めたと言わない」は守れていた。
守れていなかったのは、**読めるものを読まないまま置いていた**こと。

## 危ないのは「モデルが行き先を決める」こと

取りに行く先を決めるのは**モデル**（`read_url`）か**社長**（貼った URL）で、
**どちらもこちらの手の内ではない**。放っておけば、サーバーの中からしか見えない
ところを読ませられる — クラウドのメタデータ（`169.254.169.254`）、社内のアドレス、
`localhost`、点の無い1語の名前。

だから **行き先そのものを先に断る**（`lib/web/fetch.ts` の `blockedWhy`）。
**取ってから中身を見て判断しない。**

| 断るもの | なぜ |
|---|---|
| https 以外 | 途中で書き換えられる。`DEMO_MODE` のときだけ localhost の http を通す（検査のため） |
| 私設・ループバック・リンクローカル | 名前（`localhost` / `*.internal`）でも数字（`10.` `127.` `192.168.` `169.254.` `fd00::`）でも |
| 点の無い1語の名前 | `https://ほげ` を引きに行かせない。社内の網では1語が内側の機械に当たる |
| 既定でない口（ポート） | `:2375` のような管理用の口を叩かせない |
| URL の中の利用者名とパスワード | 認証つきの中へ入らせない |

**転送の先も毎回同じ検査に掛ける**（`redirect: 'manual'` で自分で辿る）。
1回目だけ見て通すと、そこから中へ入れる。相対の行き先は**絶対に直してから**見る。

上限は **15秒 / 2MB / 転送3回**。読めない形式（PDF・画像）は
**読めないと言う**（読めたふりをしない）。

## 栓は2つに分ける

- **社長が渡した URL** — 栓は要らない。材料を渡されただけ（取り込み・チャットに貼る）
- **社員が自分で決めた URL**（`read_url`）— **Web検索と同じ栓**に乗せる。
  これは「調べる」の一部。**設定を3つに増やさない**

## 「読む」道具は往復する

1タスク＝1往復は、道具が全部「書き残す」系だったから成り立っていた。
`read_url` は**読む**ので、読んだ結果を見てから書くことになる —
**MCP とまったく同じ仕掛け**に乗せた（結果を「社長の発言」として渡し、もう一度書いてもらう）。
渡らない社員は1往復のまま。**払う理由が無いのに往復しない。**

読めなかったときは「読めませんでした: 〜」をそのまま渡す。
**黙って空を返さない** — 社員は「読んだつもり」で書いてしまう
（憲法の「確かめていないことを言い切らない」が、そこで実際に破れる）。

## 確かめ方

```bash
npx tsx tools/check/safe.ts                    # 断り方26件（ブラウザ不要）
BASE=http://127.0.0.1:3460 npx tsx tools/check/safe.ts   # ＋ 本当に1ページ読む
BASE=http://localhost:3460 node tools/check/url.mjs 9335 # 通しの道7件
```

**危ないところは通しの検査に混ぜない。** 緩めた瞬間に中が読まれるので、1本で立てて回す。

## 残っていること

- **取り込んだ材料の中身が、画面のどこにも出ていない**（`SourceRow.summary` を
  読む画面が1つも無い）。社長が渡したものが読まれたのかどうか、社長には分からない
- 実キーでの1周（この環境は外に出られないので、読めるのは自分自身だけ）
