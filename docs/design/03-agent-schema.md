# 03 — AI社員スキーマ

参照: [msitarzewski/agency-agents](https://github.com/msitarzewski/agency-agents)（MIT・294体・20カテゴリ）
詳細は [docs/references/agency-agents.md](../references/agency-agents.md)。

## 方針

- **フォーマットは agency-agents に合わせる。** 独自形式を作らない。上流の資産をそのまま取り込めるようにする
- **294体を全部は出さない。** 統括AIが Work のゴールから 3〜5体に絞って提案する（採用画面）
- **絵文字は取り込まない。** OneFound はアイコンで職種を分類しない。識別は色だけ
- **日本語化して保存する。** 原文は `source_locale: en` として残す
- **MIT の表記を残す。** `license` と `source` を必ず持つ

## 定義フォーマット

`agent_definitions` の1レコード = 1ファイル。YAML frontmatter ＋ Markdown 本文。

```yaml
---
# ── agency-agents 由来 ───────────────────────
slug: market-researcher
source: agency-agents/research/market-researcher
source_locale: en
license: MIT
name: 調査担当
description: 市場規模・競合・顧客の調査を担い、根拠つきの調査結果を出す
category: research
color: cyan                    # 上流の color。OneFound の色トークンに写像する

# ── OneFound 拡張 ───────────────────────────
color_token: agent.cyan        # #2AA9BF — アバターの粒子はこの色だけで描く
avatar_seed: 17                # 形を固定する種。同じ社員はいつも同じ粒子になる
model_tier: standard           # deep / standard / fast
capabilities:                  # 使ってよい道具。ここに無いものは使えない
  - web_search
  - web_fetch
  - read
  - write
  - code_execution
produces:                      # 出せる成果物の型
  - doc
  - table
memory: work                   # none / work / account — 記憶の範囲
estimated_tokens_per_task: 20000
---

## Identity & Memory
あなたは調査担当。数字と出典に責任を持つ。

## Core Mission
Work のゴールに対して、意思決定に足りる粒度の事実を集め、出典つきで整理する。

## Critical Rules
- 出典のない数字を書かない。推計は推計と明示し、前提を並べる
- 承認済の決定事項に反する提案をしない。矛盾に気づいたら指摘して止まる
- 分からないことは分からないと書く。埋めない
```

## 憲法が先、定義があと（2026-08-26）

**7人ぜんぶに同じ1枚が載る**（`lib/roster/constitution.ts` → `docs/design/14-learning.md`）。
統括AIには94行の憲法があるのに、AI社員には1枚も無かった —
「分かったふりで書かない」「事業判断は自分でしない」は製品のあちこちに書いてあるのに、
**社員は一度も読んでいなかった**。

だから **Critical Rules は「その人にしか言えないこと」だけ**になった。
全員に効くこと（根拠・正直さ・事業判断は自分でしない）は憲法に上げてある。
上の例で言えば「出典のない数字を書かない」「分からないことは埋めない」は
**もう定義には書かない**（同じことを2回書かない）。

順は **憲法 → 定義 → 道具の使い方**。憲法は社員が変わっても変わらないので、
ここがプロンプトキャッシュの境目になる。

## アバターは粒子で描く

アイコンで職種を分類しない。**社員ごとに違うのは色だけ**で、形は全員同じ言語。

| 層 | 中身 | 動き |
|---|---|---|
| 球 | **点の緯度リング**を積んで球にする。手前（下側）の粒ほど明るい | とてもゆっくり回る（96秒） |
| 芯の格子 | 放射線 × 同心円のモアレ。半径21で切り抜く | 52秒で回る |
| スポーク | 球の外へ伸びる線＋先端の点 | 68秒で逆回り |
| 散り | さらに外側にまばらな粒 | 150秒で回る |
| 芯 | 色の丸＋白い点 | 3.4秒でゆっくり明滅 |

- **大きさで密度を変える**。72px以上＝全部 / 40〜71px＝間引く /
  **40px未満＝球をやめて同心リングと芯だけ**（表のアイコンで潰れないように）
- **形は種（`avatar_seed`）で固定**する。同じ社員はいつ見ても同じ粒子
- **待機中は 0.4 倍に沈め、回転を止める**。動いているかどうかが一目で分かる
- 統括AIだけ白（`#D2D2D2`）。社員ではないことを色で示す

## 上流の `color` → OneFound の識別色

AI社員は**色だけで見分ける**（形やアイコンで分類しない）。上流の色名を写像する。

| agency-agents | OneFound トークン | 値 | 使う役どころ |
|---|---|---|---|
| cyan / blue | `agent.cyan` | `#2AA9BF` | 調査・分析 |
| purple / magenta | `agent.purple` | `#9A5CD0` | 戦略・企画 |
| indigo / violet | `agent.indigo` | `#5C6BC0` | プロダクト・設計 |
| green | `agent.green` | `#34A853` | 品質・検証 |
| orange / yellow | `agent.sand` | `#B8873C` | 運用・実務 |
| red / pink | `agent.rose` | `#C06A78` | 対外・営業 |

> 意味の色（青＝次に押すもの / 緑＝済 / 橙＝判断待ち / 赤＝停止）とは**別の系統**。
> 社員の色にセマンティックな青・赤は使わない。混ざると読めなくなる。
>
> **社員の色を出すのはオフィスの絵だけ。** 表・リスト・ピルには出さない。
> 人数が増えたときに色が増えると、画面が読めなくなる。

## 社長が編集できるもの

定義（カタログ）は上流の資産なので**書き換えない**。会社ごとの差分だけを持つ。
メンバー画面の右ペインで編集できるのは、この4つだけ。

| 項目 | 何ができるか |
|---|---|
| **スキル（SKILL.md）** | 1スキル＝1ファイル。追加・編集・無効化。Claude のスキルと同じ形式 |
| **ルール** | 1行ずつ日本語で追記・削除 |
| **モデル** | 一覧から選ぶ（Claude 3枚 ＋ OpenAI 3枚）。選ばなければ既定 |
| **思考の深さ** | つまみで選ぶ。**段はモデルが決める**（受けない段は出さない） |

**道具（capabilities）は社長には触らせない。** 外部への副作用を持つ道具を素人が足せる形にしない。
必要になったら統括AIが提案し、採用と同じ確認を挟む。
編集はすぐ効くが、**走っている実行には途中から適用しない**（次のタスクから）。

## スキル = SKILL.md

タグの羅列ではなく、**Claude のスキルと同じ形**にする。1スキル＝1ファイル。

```yaml
---
name: 競合分析のやり方
description: 競合を並べて比較するとき。ポジショニングや価格の比較を頼まれたら読む
---

## 手順
1. 競合を5〜8社に絞る。選んだ理由を1行で書く
2. 比較軸は「価格 / 対象 / 強み / 弱み」の4つから始める
3. 表にする。出典URLを各セルに残す

## この会社での注意
- 韓国市場では △△ を必ず含める（社長の指示・8月18日）
```

保存先は `agent_skills`。

| 列 | 意味 |
|---|---|
| `id, account_id` | |
| `employee_id` | どの社員のものか。**null なら会社共通**（全社員が使える） |
| `filename` | `competitor-analysis.md` |
| `name, description` | frontmatter から抜いたもの。**description が読み込み判定に使われる** |
| `body` | Markdown 本文 |
| `source` | `builtin`（定義に同梱）/ `user`（社長が書いた） |
| `enabled` | 無効にできる。消さずに止められる |

- `builtin` を編集すると**フォークして `user` 版を作る**。上流の更新は取り込み続けられる
- 会社共通スキル（`employee_id` が null）で「うちの書き方」を全社員に効かせられる

### スキルとルールの違い

ここを混ぜると壊れる。

| | スキル（SKILL.md） | ルール |
|---|---|---|
| 何を書くか | **やり方の手順書** | **常に守る制約** |
| いつ読まれるか | **必要なときだけ**（`description` で判定） | **毎回**（システムプロンプトに常駐） |
| 長さ | 長くてよい | 1行。短く |
| 例 | 「競合分析のやり方」 | 「出典のない数字を書かない」 |

Claude Code の **Skills と CLAUDE.md の関係**と同じ。
ルールは**追記のみ**で、定義側の Critical Rules は消せない
（「出典のない数字を書かない」を消せてしまうと壊れる）。

## モデルと思考の深さ

**社長が一覧から選ぶ**（2026-08-25 に実装。それまでは押しても何も残らなかった）。
一覧は `lib/ai/catalog.ts` の1枚だけ — 画面のプルダウンも、実行に渡す名前も、
原価の単価も、深さの段も、ここを見る。**2か所に書かない。**

| 見出し | モデル | 1語 |
|---|---|---|
| Claude | Claude Opus 5 | じっくり |
| | Claude Sonnet 5 | ふだん |
| | Claude Haiku 4.5 | 速い |
| OpenAI | GPT-5.6 Sol | じっくり |
| | GPT-5.6 Terra | ふだん |
| | GPT-5.6 Luna | 速い |

- **名前だけでは選べない**ので、右に**1語だけ**添える（速い / ふだん / じっくり）。
  階層の語をそのまま使う — 新しい言い方を作らない
- **値段は出さない。** 数字を出していいのは請求とプランの画面だけ
- **Thinking 版を一覧に並べない**（それは深さの仕事）。
  `openai/gpt-5.6-luna-pro` は Luna の thinking 版なので載せない
- 「エコ」のような独自の言い方はしない

**思考の深さはつまみ**（参考: Claude Code のエフォート）。粒のグリッドが右へ行くほど
明るくなり、白いつまみで止める。左端が **考えずに答える**、右端が **いちばん深く**。
段階のピルにしない。

| 段 | 言葉 |
|---|---|
| `none` | 考えずに答える |
| `low` | 浅め |
| `medium` | 標準 |
| `high` | やや深め |
| `xhigh` | 深め |
| `max` | いちばん深く |

- **段と言葉は1対1。** 前は段が5つ・言葉が6つで、つまみの位置がどの段を指すのか
  誰にも言えなかった
- **段はモデルの持ちもの。** Claude に `none` は無く、**Haiku 4.5 は深さを受けない**。
  **受けない段を出さない** — 選んだ瞬間にその往復ごと上流で弾かれる。
  1段も持たないモデルでは**つまみごと出さない**（押せない行を置かない）
- **深さでモデルは変わらない。** 深さは thinking の量

**保存ボタンは置かない。** モデルも思考の深さもスキルのトグルも、**切り替えたその場で効く**。

```sql
-- agent_prefs（0024 / 0025）。employee_id が null なら統括AI
employee_id uuid     -- null = 統括AI（employees に行を持たない）
model       text     -- 通り道での名前（catalog の id）
effort      text     -- none | low | medium | high | xhigh | max
paused      boolean  -- 止めているあいだ、新しいタスクは起こされない
```

**一時停止を `employees.status` に持たせない。** あの列は「いま何をしているか」で、
実行のたびに running → idle と書き換わる（＝止めた印が次の実行で消える）。
止めるかどうかは社長が決める**設定**なので、モデルと深さと同じ場所に置く。
走っている最中のものは最後までやる — 途中で切ると、書きかけの成果物が宙に浮く。

実効値は2層。**下が勝つ。**

1. 既定（`DEFAULT_PREF` — 統括AIは `deep` の表のモデル・やや深め／社員は `standard` の表のモデル・浅め）
2. 社員ごとの設定（`agent_prefs`）

**まだ選んでいない人は既定の姿を画面に出す。** 実行もその既定で走るので、
画面と実物が食い違わない（「自動」のような、どこにも無い言葉を出さない）。

**統括AIの深さが効くのは計画と判断のとき。会話の返事はいつも速く返す。**
相談のたびに深く考えると、チャットとして成立しない（社長が「遅い」と言ったのはここ）。

### 判断ログ（2026-08-25）— 自動 / 手動をやめた

元の設計は **自動 / 手動の2択 ＋ 会社の既定 ＋ 3層の重ね**だった。作るときに落とした:

- **「自動」を名乗るには、自動で選ぶ側が要る。** それは Model Router で、
  実モデルの品質と原価の実測が無いうちは作らない（→ `docs/PLAN.md` 見送りの台帳）。
  無いものを既定として画面に出すと、**そこだけ嘘になる**
- **会社の既定（`accounts.defaults`）は置かなかった。** `accounts` に UPDATE の
  ポリシーが無い（社長に書かせない表）。1人1行の `agent_prefs` で足りる
- **`employee_settings` は落とした**（0024）。0行・参照0か所で、`model_fixed` が
  階層名（fast/standard/deep）に縛られた別設計だった。**一時停止はここに足した**（0025）。
  ルールを社長が足せるようにするときも、同じ表に列を足す

### いつか自動で選ぶなら

| タスクの性質 | 段 |
|---|---|
| 抽出・整形・要約・分類・定型の下書き | `fast` |
| 通常の調査・執筆・設計・レビュー | `standard` |
| 分岐の多い設計、計画づくり、重要な判断の下書き | `deep` |

**この節はまだ絵に描いた餅。** いまは階層ごとに呼び分ける口（`tier`）だけがあり、
どの階層でも同じ表のモデルが当たる。自動で選ぶ側を作るときに、上の一覧の上に乗せる。

- 段は**タスクの kind と入力量**から決める。社長には見せない
- `deep` は**1 Work あたりの回数に上限**を置く。当たったら `standard` に落として続ける
- 思考の深さは既定 `低`〜`中`。**行き詰まったときだけ1段上げて1回だけ再試行**する
- 統括AI自身（計画・判断・会話）は常に `deep`。ここを削ると全体が壊れる
- **1タスクのトークン上限は内部の安全弁**。画面には出さない（→ [05](./05-tech-and-cost.md)）

## 初期ロスター（Phase 3 で入れる）

まず6体だけ入れる。増やすのは後からデータを足すだけ。

| 名前 | slug | 色 | 何をするか |
|---|---|---|---|
| 調査担当 | `market-researcher` | cyan | 市場規模・競合・顧客の調査 |
| 戦略担当 | `business-strategist` | purple | 収益モデル・価格・優先順位 |
| 企画担当 | `product-manager` | indigo | 要件・仕様・ロードマップ |
| 執筆担当 | `content-writer` | sand | LP・記事・投稿の文章 |
| 分析担当 | `data-analyst` | cyan | 数値の集計・シミュレーション |
| 品質レビュアー | `quality-reviewer` | green | 成果物のチェックと差し戻し |

## 記憶（memory）

| 範囲 | 意味 | 実装 |
|---|---|---|
| `none` | 毎回まっさら | メモリを渡さない |
| `work` | その Work のあいだだけ覚える | Work ごとに memory store を1つ |
| `account` | 会社をまたいで覚える（社風・好み） | 会社に1つ、全社員で共有 |

**秘密情報はメモリに書かない。** APIキー等は資格情報の保管庫（vault）に置き、実行時に注入する。
メモリは後続の全セッションにそのまま再生されるため、一度書くと消し切れない。

## 権限

`capabilities` に書いていない道具は、そのAI社員には渡さない。
外部への副作用（送信・公開・課金・削除）を伴う道具は、`capabilities` に入っていても**実行前に必ず確認を挟む**（→ [02](./02-executive-model.md) 人間ゲート）。
