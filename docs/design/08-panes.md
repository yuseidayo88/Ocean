# 08 — 右ペインの2つの形

> 判断ログ（2026年8月）。Phase 4 のレビューで「全部がタブになっている」と指摘されて決めた。

## 何が問題だったか

実装した12画面すべてが、右ペインを**タブの器**（角丸の面 ＋ 中に ✕ ＋ 右上に ＋）で出していました。
中身は「タスクの詳細」「AI社員の設定」「診断の1件」など、**選び直したら入れ替わるもの**ばかりです。
タブは「複数を開いたまま持ち歩く」ための形なので、そこに1件しか入らないものを入れると、
**閉じても増やしても意味がない飾り**になります。

これは `ブラウザの真似をしない`（戻る・進む・再読込と `onefound://` を撤去した）と同じ間違いが、
小さく戻ってきていた状態でした。

## 見分け方

> **選び直したら入れ替わってほしいものはパネル。残っていてほしいものはタブ。**

言い換えると、**持ち出して読み比べる「文書」だけがタブ**です。
決めるもの・設定するものは、1件ずつ片づける作業なので、同時に2つ開く理由がありません。

## いつ開くか

> **閉じた状態から始まる。中身を押すと開く。**

- 最初は**右に何も出ていない**。中央が画面いっぱいに使える
- **一覧の行やカードを押すと、その1件のぶんだけ開く**（押した行は面で選択中と分かる）
- **✕ で閉じると、右の端には何も残らない**（開き直すためのつまみを置かない）
- 戻り道は**トップバーの左端の板アイコン**。もともとそこにあって何もしていなかったものを、
  右ペインの出し入れに割り当てた

行がない画面（Work・計画の承認）は付き添いのパネルなので、押す行がない。
その2枚は板アイコンだけで出し入れする。

## 左レールも同じ作法

- **閉じる印はレールの中**（上の行、窓の印の右）。器の開け閉めは器の中にある
- **閉じたら左の端に何も残さない。** 戻り道はトップバーの左端
- **絵と役目を合わせる** — 左向きの板アイコンは左レール、右向きは右ペイン。
  以前は左向きの絵で右ペインを動かしていた
- **会社の切り替えはレールから出してパンくずの根へ**（`会社名1 ⌄ / タスク`）。
  いま見ているものは全部この会社のものなので、行き先の親として置くのが正しい。
  レールを閉じても消えない

## 2つの形

### パネル（既定）

- 46px の見出し行 — 小さいアイコン ＋ **素の文字** ＋ 右端に ✕
- **タブの器を作らない。＋ も置かない**
- 行を選び直すと中身が入れ替わる。閉じれば中央が広がる
- **見出しは押した行の名前**（「タスクの詳細」のような器の名前にしない）

使うところ:

| 画面 | 中身 |
|---|---|
| ④ Work | この Work について（画面の付き添い。行の詳細ですらない） |
| ② 計画の承認 | この計画の根拠 |
| ⑤ タスク | 選んだタスクの詳細 |
| ⑨ メンバー | AI社員の設定 |
| ⑧ 採用 | 候補の詳細 |
| ⑩ 通知 | 選んだ通知の中身 |
| ⑦ 決定事項 | 選んだ判断 |
| ⓪-b 候補 | この案をすすめる理由 |
| ⓪-c 取り込み | 選んだ取り込み元 |
| ⓪-d 診断 | 選んだ1件 |

### タブ

- いままでの器のまま。✕ で閉じ、**＋ で足す**
- **画面を移っても開いたまま**（Phase 5 以降でセッションに持つ）

使うところ:

| 画面 | 中身 | なぜタブか |
|---|---|---|
| ⑥ 成果物 | 開いた成果物 | 収益モデル比較と市場調査を**見比べる** |
| ⑫ スキル | 開いた SKILL.md | ファイル。1本書きながら別の1本を参照する |

## 迷ったもの

- **決定事項** — 静止画は「価格モデル」「無料期間」の2タブでした。
  価格と無料期間は互いに効くので、並べたい気持ちは分かります。
  それでも**判断は1件ずつ確定させるもの**で、確定したらタブは用済みになります。
  → **パネル**。並べて比べたいなら、それは判断ではなく成果物（比較レポート）の仕事

## ついでに決めたこと

- **1つの中の行き先（概要 / 履歴 / 資料）はタブではない。** ペインの中に置く**選ぶ列**にする。
  外側のタブは「何を開いているか」、内側の列は「その中のどこを見ているか」。混ぜない
- 行動の行（ペインの下）は2つの形がある
  - **青が幅いっぱい** — 成果物・通知・決定事項（そのペインで決着させる）
  - **小さい2つ、青が右** — 採用・診断（別の画面へ続く）

## 器の最小幅 — 1408px

右ペインは幅が決まっている（400〜480）。窓が狭くなると中央だけが縮み、
**表のタイトル列が 0px まで潰れて中身が消えていた**（1120px で `/tasks` の
タイトル列と `/team` の「いまの担当」列が丸ごと消えることを実測）。

中身を縮めて隠すのではなく、**窓のほうを横に滑らせる**ことにした。

```
SHELL_MIN = 1408  = 左レール 260 ＋ 盤面 1148
```

1148 は オフィス と ワークフロー の絵の幅で、これは縮まない（絵なので）。
だから会社全体の最小幅もここで決まる。1408 より狭い窓では
`app/(app)/layout.tsx` の外側が `overflow-x: auto` になり、器ごと横に動く。

**画面ごとのブレークポイントは作らない。** 表の列を隠したり、ペインを重ねたりすると
「どの画面でどう変わるか」を覚えることが増える。1本の規則で全画面が同じ振る舞いになるほうがいい。

### 確かめかた

`?open=` を URL に持っているので、開いた状態と閉じた状態を機械で回して比べられる。
1408 / 1440 / 1920 の3つの幅で、20画面 × 開閉の両方を通し、
**…で切れる文字・画面外に出る文字・閉じたときと比べて消える文字**がゼロであることを確認した。

## タブは本物にする

**成果物** と **スキル** はタブの形にしていたが、**中身が入れ替わっていなかった**。
`/deliverables` は2枚目のタブが文字だけのハリボテで、押しても1枚目の文書が出たまま。
`/skills` はどの行を押しても `competitor-analysis.md` が出ていた。
「持ち出して読み比べる文書だからタブ」と言っておいて、読み比べられなかった。

直したかたち:

```
?open=d-rev,d-mkt&at=1
```

- **並びは動かさない。** 押すたびに順番が変わると読み比べができない
  （最近見た順に並べ替えるのは、行き来する用途と相性が悪い）
- **いま見ているものは `at`。** 1枚だけのときは省く
- **同じものを2枚開かない。** すでに開いていればそのタブへ移るだけ
- **✕ はそのタブだけ閉じる**（ペイン全体ではない）。閉じたら右隣へ、無ければ左隣へ
- まだ書けていない成果物（生成中）も開ける。中身のかわりに `PaneLoading` を出す

`lib/use-open.ts` の `useTabs()` が並びと現在地を1回で書き換える（片方が古いまま上書きされない）。
中身は `DELIVERABLE_BODY` と `SKILL_BODY` に1件ずつ持つ。**画面に文章を書かない。**


## 閉じる印を2つ置かない

右ペインを開くと、**ペインの中の ✕** と **トップバー右端の板アイコン**の2つが出ていた。
どちらも「閉じる」なので、同じことを2回言っている。

**左レールとまったく同じ作法に揃えた。**

    開け閉めは器の中にある     ── ペインの中の ✕
    閉じたら端に何も残さない
    戻り道はトップバー         ── 閉じているときだけ板アイコンが出る

開いているあいだ板アイコンは幅 0 に畳む（消したり出したりしない。横の並びが飛ばない）。

## 入らないときはタブの名前を出さない

成果物を4枚5枚と開くと、名前を全部出そうとして押し込むので、どれも読めない幅になっていた。

**見ているタブだけ名前を出し、ほかは印だけに畳む。** 押せばそれが開いて名前が出る。

| 開いている数 | どう見えるか |
|---|---|
| 1〜2枚 | 全部に名前。見ているほうを少し広く取る（1.7 : 1） |
| 3枚以上 | 見ているタブだけ名前 ＋ ✕。ほかは 26px の印だけ |

分かれ目は **名前に 112px（日本語で7〜8文字）取れるかどうか**。
これを割るくらいなら出さないほうがいい — 「市場調…」が並んでも見分けられない。

幅は決まっているので**測らずに決める**（ペインの幅から引き算するだけ）。
畳んだタブにも薄い面を敷いて、押せるものだと分かるようにする
（「面と枠を持てるのは押せるものだけ」— タブは押せる）。

名前は**わざと**切っているので `clip` の印をつけ、機械の点検が拾わないようにした。


## どの画面からでも統括AIと話せる

入力欄に書いて Enter を押すと、**右ペインがその会話になって開く。入力欄はその中へ移る。**

### なぜ入力欄も一緒に移るのか

Mobbin で「右にAIパネルを出すアプリ」を並べて見た —
[ClickUp Brain](https://mobbin.com/screens/eee7da65-c3d6-49a3-8b32-0cf3d64e5730) /
[Fabric](https://mobbin.com/screens/b392bc22-bf75-4b35-be0a-ae58de609dc2) /
[HoneyBook](https://mobbin.com/screens/fa243020-70b3-41a7-94c1-50e5d51c7355) /
[HubSpot](https://mobbin.com/screens/2421e56a-c26b-4e1a-85fa-5645153c6b86) /
[Customer.io](https://mobbin.com/screens/fafcbfb9-fa85-4b4d-b17f-54df962305b5)。

**例外なく、入力欄もパネルの中にある。** 読む目と書く手が別の場所にあると落ち着かない。
「入力欄は全画面で同じものを1つ」という決まりは破れていない — **1つのまま、場所が変わる**。

### 決めたこと

- **右ペインの3つめの形は作らない。** これはパネル（画面そのものの付き添い）の一種。
  見出し ＋ ✕ の作法は同じ。持ち出して読み比べるものではないのでタブにもしない
- **右は1枚だけ。** 会話を開くと画面側のペインは引っ込み、行を選び直すと会話が引っ込む。
  「押しても何も出ない」をつくらない
- **どのスレッドに書くか**は画面が決める。Work の画面ならその Work のスレッド、
  それ以外は新しいチャット。見出しにスレッド名が出る
- 見出しの右は **＋（新しいチャット）** と **⤢（チャット画面へ）**。
  チャット画面は既にあるので、専用の全画面表示は作らない
- **チャット画面では出さない。** そこは会話そのものが主役なので、右に同じものを重ねない
- **返事は作らない。** 書いたものは出るが、統括AIは「考えています」で止まる（Phase 5 まで）。
  嘘の返事を出すくらいなら、繋がっていないと分かるほうがいい

### 盤面のある画面（オフィス / ワークフロー）

盤面は 1148×760 の**絵**。右に 430 の会話を開くと、1440 の窓では横幅が足りない。

器ごと広げて窓を横スクロールさせると、**開いた会話そのものが画面の外に出てしまう**ので、
**絵のほうを入る大きさに縮める**ことにした（100% を超えては拡大しない）。
ツールバーの数字はいま実際に縮んでいる率を言う（`63%`）— **数字と絵を食い違わせない**。

**文字は縮めない。縮んでいいのは絵だけ。**
