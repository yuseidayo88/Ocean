# 08 — 右ペインの2つの形

> 判断ログ（2026年8月）。Phase 4 のレビューで「全部がタブになっている」と指摘されて決めた。

## 何が問題だったか

実装した12画面すべてが、右ペインを**タブの器**（角丸の面 ＋ 中に ✕ ＋ 右上に ＋）で出していました。
中身は「タスクの詳細」「AI社員の設定」「診断の1件」など、**選び直したら入れ替わるもの**ばかりです。
タブは「複数を開いたまま持ち歩く」ための形なので、そこに1件しか入らないものを入れると、
**閉じても増やしても意味がない飾り**になります。

これは `ブラウザの真似をしない`（戻る・進む・再読込と `onefound://` を撤去した）と同じ間違いが、
小さく戻ってきていた状態でした。

## 見分け方

> **選び直したら入れ替わってほしいものはパネル。残っていてほしいものはタブ。**

言い換えると、**持ち出して読み比べる「文書」だけがタブ**です。
決めるもの・設定するものは、1件ずつ片づける作業なので、同時に2つ開く理由がありません。

## いつ開くか

> **閉じた状態から始まる。中身を押すと開く。**

- 最初は**右に何も出ていない**。中央が画面いっぱいに使える
- **一覧の行やカードを押すと、その1件のぶんだけ開く**（押した行は面で選択中と分かる）
- **✕ で閉じると、右の端には何も残らない**（開き直すためのつまみを置かない）
- 戻り道は**トップバーの左端の板アイコン**。もともとそこにあって何もしていなかったものを、
  右ペインの出し入れに割り当てた

行がない画面（Work・計画の承認）は付き添いのパネルなので、押す行がない。
その2枚は板アイコンだけで出し入れする。

## 左レールも同じ作法

- **閉じる印はレールの中**（上の行、窓の印の右）。器の開け閉めは器の中にある
- **閉じたら左の端に何も残さない。** 戻り道はトップバーの左端
- **絵と役目を合わせる** — 左向きの板アイコンは左レール、右向きは右ペイン。
  以前は左向きの絵で右ペインを動かしていた
- **会社の切り替えはレールから出してパンくずの根へ**（`ことのは ⌄ / タスク`）。
  いま見ているものは全部この会社のものなので、行き先の親として置くのが正しい。
  レールを閉じても消えない

## 2つの形

### パネル（既定）

- 46px の見出し行 — 小さいアイコン ＋ **素の文字** ＋ 右端に ✕
- **タブの器を作らない。＋ も置かない**
- 行を選び直すと中身が入れ替わる。閉じれば中央が広がる
- **見出しは押した行の名前**（「タスクの詳細」のような器の名前にしない）

使うところ:

| 画面 | 中身 |
|---|---|
| ④ Work | この Work について（画面の付き添い。行の詳細ですらない） |
| ② 計画の承認 | この計画の根拠 |
| ⑤ タスク | 選んだタスクの詳細 |
| ⑨ メンバー | AI社員の設定 |
| ⑧ 採用 | 候補の詳細 |
| ⑩ 通知 | 選んだ通知の中身 |
| ⑦ 決定事項 | 選んだ判断 |
| ⓪-b 候補 | この案をすすめる理由 |
| ⓪-c 取り込み | 選んだ取り込み元 |
| ⓪-d 診断 | 選んだ1件 |

### タブ

- いままでの器のまま。✕ で閉じ、**＋ で足す**
- **画面を移っても開いたまま**（Phase 5 以降でセッションに持つ）

使うところ:

| 画面 | 中身 | なぜタブか |
|---|---|---|
| ⑥ 成果物 | 開いた成果物 | 収益モデル比較と市場調査を**見比べる** |
| ⑫ スキル | 開いた SKILL.md | ファイル。1本書きながら別の1本を参照する |

## 迷ったもの

- **決定事項** — 静止画は「価格モデル」「無料期間」の2タブでした。
  価格と無料期間は互いに効くので、並べたい気持ちは分かります。
  それでも**判断は1件ずつ確定させるもの**で、確定したらタブは用済みになります。
  → **パネル**。並べて比べたいなら、それは判断ではなく成果物（比較レポート）の仕事

## ついでに決めたこと

- **1つの中の行き先（概要 / 履歴 / 資料）はタブではない。** ペインの中に置く**選ぶ列**にする。
  外側のタブは「何を開いているか」、内側の列は「その中のどこを見ているか」。混ぜない
- 行動の行（ペインの下）は2つの形がある
  - **青が幅いっぱい** — 成果物・通知・決定事項（そのペインで決着させる）
  - **小さい2つ、青が右** — 採用・診断（別の画面へ続く）

## 器の最小幅 — 1408px

右ペインは幅が決まっている（400〜480）。窓が狭くなると中央だけが縮み、
**表のタイトル列が 0px まで潰れて中身が消えていた**（1120px で `/tasks` の
タイトル列と `/team` の「いまの担当」列が丸ごと消えることを実測）。

中身を縮めて隠すのではなく、**窓のほうを横に滑らせる**ことにした。

```
SHELL_MIN = 1408  = 左レール 260 ＋ 盤面 1148
```

1148 は オフィス と ワークフロー の絵の幅で、これは縮まない（絵なので）。
だから会社全体の最小幅もここで決まる。1408 より狭い窓では
`app/(app)/layout.tsx` の外側が `overflow-x: auto` になり、器ごと横に動く。

**画面ごとのブレークポイントは作らない。** 表の列を隠したり、ペインを重ねたりすると
「どの画面でどう変わるか」を覚えることが増える。1本の規則で全画面が同じ振る舞いになるほうがいい。

### 確かめかた

`?open=` を URL に持っているので、開いた状態と閉じた状態を機械で回して比べられる。
1408 / 1440 / 1920 の3つの幅で、20画面 × 開閉の両方を通し、
**…で切れる文字・画面外に出る文字・閉じたときと比べて消える文字**がゼロであることを確認した。
