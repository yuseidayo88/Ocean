# 図（ワークフロー）

社長の指示（2026-08-25）:
> work のワークフローチャート作成する時 https://github.com/tt-a1i/archify この skill を適応するようにしたい

## archify とは

エージェント用のスキル（MIT）。JSON の仕様から**自己完結した HTML の図**を作る。
5種類 — Architecture / **Workflow** / Sequence / Dataflow / Lifecycle。
作法がはっきりしている:

- 主線を1本にして、枝は**いちばん近い主線のノード**から出す
- 主要ノードは**12個まで**、ラベルは意味のあるものだけ
- 固有名詞（商品名・API・環境名）はそのまま写す
- **検証を全部通してから出す。通ったら凍結して、あとから編集しない**
- **直らなかった診断は正直に報告する**

## そのままは持ち込めなかった

archify の手順は `archify.mjs validate → deliver → visual-check` という
**Node の CLI が前提**。OneFound の AI社員は**1タスク＝1往復・道具は4つ**で、
シェルもファイルシステムも無い。成果物も `deliverables.body` のテキストで、
HTML を描く場所が無い。

→ **持ち込むのは「形」と「作法」、検証は OneFound の中で回す。**

| | archify | OneFound |
|---|---|---|
| 器 | `schema_version` / `diagram_type` / `meta` / `lanes` / `phases` / `mainPath` / `nodes` / `edges` | **名前ごと同じ**（`lib/diagram/types.ts`） |
| 検証 | `archify.mjs validate`（9つ） | **`lib/diagram/check.ts`（9つ）**。CLI が要らない |
| 描く | 自己完結 HTML（archify のテーマ） | **この会社のデザイン言語**（`components/diagram/Workflow.tsx`） |
| 直し | 診断された対象だけ直す | **同じ**（`redraw`。道具を1つに絞ってもう一度だけ） |

### 落としたもの

`brand` / `visual_preset` / `animation` / `cards` / `views` — 飾り。
「面と枠を持てるのは押せるものだけ」に反する。
`legend` — **凡例を置かない**（凡例が要るなら形のほうが間違っている）。
`groups` — レーンとフェーズで足りる（入れ子は1段まで）。
`width` / `height` / `route` / `via` / `channelX` … — archify の描画器を手で操る値。
**こちらは格子が位置を決める**ので要らない。

### 変えたもの

`node.type`。archify は `frontend / backend / database …`（システム構成の語）だが、
一人社長のワークフローでは意味を持たない。
**`work / decision / deliverable / wait / end`** に変えた。
色が付くのは2つだけ — **decision＝橙**（あなたが決める）/ **end＝緑**（到達）。
ほかは灰。例外のレーンは点線で沈める。

## 9つの検査

絵が壊れるか、読めなくなるものだけを見る（通らない規則を並べない）。

| | 見るもの | 壊れる |
|---|---|---|
| ① | id が重複していない | ● |
| ② | 線の元と先が実在する | ● |
| ③ | レーンが実在する | ● |
| ④ | 主線が2つ以上あり、順に線で繋がっている | |
| ⑤ | ノードは12個まで | |
| ⑥ | 迷子のノードがいない | |
| ⑦ | 枝は主線のノードから出る | |
| ⑧ | 同じレーンの同じ列に2つ置かない | ● |
| ⑨ | 名前が空でない・同じ名前が2つない | ●（空だけ） |

**● は「絵が壊れる」** — 出さずに、指したところだけ直してもらう（1回だけ）。
それでも壊れていれば、**通らなかったと正直に言う**（壊れた図を成果物にしない）。
●でないものは出したうえで、**直らなかったこととして成果物に残す**。

## 描き方

格子（列 198px・段 104px・ノード 176×60）／**直角に曲がる線**（角だけ丸める）／
**左3pxの色帯 ＋ タイトル ＋ サブ1行**／ドットの背景。
**ホームのワークフローの地図とまったく同じ語彙** — 同じ会社の中で2つの図法を作らない。

地図と違うのは1つだけ: **これは動かさない。**
成果物は読むもので、探すものではない（地図は Work が3〜8本、図は12ノードまで）。
器に合わせて1枚に収める — 拡大縮小の道具も、ミニマップも置かない。

## 道具

`draw_workflow`（`lib/run/tools.ts`）。**`write_deliverable` の代わり**で、
1タスクに1つ。**座標は書かせない** — `lane` と `col` だけ決めれば格子が置く。

作法は標準スキル `workflow-diagram.md` に入っている（社長にも見える・切れるが消せない）。

## ホームのワークフローの盤面にも当てる（2026-08-25）

社長の指示は**こちらが本命**だった:
> このスキル使って欲しいのは ホームのワークフローの画面組み立てる時です

組み立てを `lib/live/flow.ts` の1か所にまとめ、archify の作法を3つ当てた。

### ① 主線を1本にする

前は Work が**対等に縦へ積まれていて**、「いまどれを見ればいいか」が
盤面のどこにも出ていなかった。**放っておけない順**
（判断待ち → 要確認 → 順調。タスク一覧・進捗とまったく同じ規則）の1本目を主線にして、
**いちばん上の段**に置く。主線の鎖は**線を太く引く**（1.9 / 1.3）。
**色は増やさない** — 明るさと太さで言う。

### ② 枝は、いちばん近い主線のノードから出す

前はチップ（判断・要確認）の列を `Math.max(nowSeq, 1)` で決めていて、
**畳んだあとの列とずれていた**。しかも単独チップの線が**2点しかなく**、
列がずれた瞬間に**斜めの線**になっていた（この会社の決まりは直角の線）。

- **畳みを組み立て側に移した** — 列を決める場所を1つにする
- チップは**親のフェーズと同じ列**（＝真下）
- 線は**4点の直角**にした（2点だと必ず斜めになる）

`MapPhase.span` を足して、**畳んでも元のフェーズ番号を失わない**
（「フェーズ 1〜2 · 完了」の次は「フェーズ 3」）。

### ③ ノードは12まで

超えたら、済んだフェーズを **Work ごと1枚に畳む**。
一目で読めない盤面は、地図として役に立たない。

### 検証

組んだ盤面を**同じ9つの検査**に掛ける。通らなければ**描かずに正直に言う**
（壊れた地図は嘘をつく）。④と⑦は盤面では意味が変わるので見ない
（フェーズが1つの Work に主線は無い）。
