# 進行計画

最初のマスタープロンプトで決めた **Phase 0 〜 10** を、いまの決定に合わせて更新したもの。
フェーズの番号と区切りは原文のまま。中身だけ、Phase 0〜2 で決まったことを反映しています。

## 守るルール

原文の「Claude Code Working Rules」24項目を、いまの言葉でまとめ直したもの。

### 進め方

- **フェーズを飛ばさない。** 各フェーズの終わりで**必ず停止**する
- 停止するときは5つを報告する — **何をしたか / 変更点 / 確認できるもの / 次の予定 / 判断が必要なこと**
- **明示的な承認なしに次へ進まない。** 「ついでに次も作っておきました」は禁止
- 一気に全部作らない。次フェーズの実装を先回りしない
- 大きな仕様変更を、理由を説明せずにしない

### プロダクト

- **特定の業種にハードコードしない**
- **Chat 中心の UI にしない。** 主役は「会社が動いている状態」
- **偽の進捗を出さない。** 画面の状態＝バックエンドの状態
- **重要な情報を会話履歴だけに保存しない。** 決定は構造化して残す
- **成果物を会話から分離する**
- **高度なAI設定（モデル・思考量）は一般ユーザーから隠す**
- AI社員の人数より **Work の完了**を優先する
- セキュリティとプライバシーを速度のために犠牲にしない

## 元の要件から変えたこと

| | 原文 | いま | 理由 |
|---|---|---|---|
| モデル調達 | OpenRouter | **Anthropic と OpenAI に直接** | 原価が読めることを優先。仲介の利点（自動迂回）は2社直結で足りる |
| ホスティング | Next.js ＋ Supabase | **Cloudflare** ＋ Supabase（Postgres/Auth） | 1実行 = 1 Durable Object。二重起動が起きず、進捗を WebSocket で直接押せる |
| 思考量のUI | Fast / Balanced / Deep をユーザーに見せる | **見せない**（`deep`/`standard`/`fast` は内部だけ） | 「毎回考えなくていい」という製品思想と、選ばせるUIが矛盾していた |
| ナビゲーション | Office / Work / Tasks / Deliverables | ホーム / 通知 / Work / **用事** / タスク / 成果物 / メンバー / 決定事項 | Office をホームに改名し可視化の場に。決定事項と用事を独立させた |
| 単発の依頼 | （定義なし） | **用事**（計画も承認もなし・1タスク・上限3万トークン） | Work の器を着せると要らないものが全部ついてくる |
| Work の粒度 | （定義なし） | 判定条件3つ＋昇格・降格 | 「LPが目標の Work も過程の Work もある」問題への答え |
| 課金の単位 | Credits（将来） | **トークン**（1 = $0.00001） | 画面に出す数字を実感のある桁にした |

## まだ設計に落ちていない要件

原文にあって、いまの21画面・7文書でまだ埋まっていないもの。**10件すべて MVP スコープに入れます。後回しにしません。**

いまの設計は原文の **Case A（作りたいものが決まっている）にしか対応できていません。**
Case B（何をやればいいか分からない）と Case D（既存事業を改善したい）は、画面もデータモデルも空白です。

## Phase 3 に入る前にやること

**A の4件（画面6枚＋データモデルの追記）を1ラウンドで設計します。**
これは Phase 1 の続きなので、新しいフェーズ番号は振りません。

終わったら、その先の見た目の磨き込みは **Phase 4（ダミーデータで全画面）でやります。**
静止画で判断できることには限りがあるので、**Phase 4 が本当のUI/UXレビューの場**です。

### 任意 — 早めにやると安いこと

**画面を作らずに、1タスクだけ API で走らせて成果物を見る。**

この製品の一番大きな未知は「AI社員が出してくる成果物の質」です。
**それはUIをいくら磨いても分かりません。** 逆に、スクリプト1本（半日）で分かります。

分かること: 市場調査レポートが実用に足るか ／ 1タスクの実トークンと実時間 ／
憲法とAI社員の定義文をどう直すべきか ／ 原価の見積もりが合っているか

Phase 3 の前でも後でも構いませんが、**早いほど得です。**

## MVP でやらないこと（原文のまま）

3D Office ／ 複雑なアバター ／ 社員のレベル ／ マーケットプレイス ／ Gmail 自動送信 ／ Slack 自動化 ／
Stripe 操作の代行 ／ GitHub 自動マージ ／ 複雑な権限 ／ 完全自律の長期エージェント ／ 高度な長期記憶 ／
複数会社 ／ モバイルネイティブ ／ 複数人での共同編集

**あとから拡張できる形にはしておく。いま作らない。**
