# 社長のこと

**会社が社長から覚えたこと**（Hermes の `USER.md` / user modeling にあたる）。
`CLAUDE.md` は「何を作るか」、ここは「**どう進めるか**」。

**でっち上げない。** 書くのは、実際に言われたこと・実際に起きたことだけ。
違っていたら消してください（消せることに意味がある）。

---

## 判断のくせ

- **順番は「作る → 整える → 公開する → そこから広げる」。**
  マーケティング・集客・営業は**後ろ**。2回言われている
  （LPの例／「マーケティングを最後の方にして欲しい」）。先に声をかけるのは間違い
- **受注や問い合わせを、フェーズにしない。** 他人が動かないと終わらないものは、
  こちらの仕事ではない
- **「押せる以上、本物にする」。** 本物にしないなら押させない
  （会社の切り替えは、複数社をやらないと決めたので素の文字にした）
- **画面が1つ減るほうを選ぶことがある。**「てかこの画面いる？」で進捗ビューを畳んだ。
  見やすくなった＝要る、ではない

## 報告のしかた

- **直した報告より、何が嘘だったかを先に。** 「動くと書いてあるのに動いていない」を
  いちばん重く見る。直したふり・動いているふりを、はっきり嫌う
- **確かめていないことは「確かめていない」と書く。** 実キーで通していないなら、そう言う。
  丸めた報告は、あとで必ず崩れる
- **測ってから直す。** 「感想では直せない」（往復の数を数えてから prefetch を外した）
- 長い前置きは要らない。**結論 → 根拠 → 次の一手**の順

## 進め方

- **ひとりで通しでやってほしい。** 途中で細かく聞かれるより、
  やって・確かめて・push して・報告してほしい。判断が要るところだけ聞く
- **やり切る。** 「宿題は全部やる。後回しにしない」
- **自分でも触る。** 実キーで触って穴を見つけて持ってくることがある。
  そのとき見つかるものは、たいてい**この環境では出ない種類**の穴
- 気持ちが落ちることがある。**そのときは飾らずに、実物を見せるのがいちばん効く**

## 言葉

- 日本語。コメントも commit も docs も
- **状態の語は6つだけ**（判断待ち / 要確認 / 実行中 / 待機 / 完了 / 承認済）。
  この外に新しい言い方を作らない
- カタカナ語は日本語にできるならする
